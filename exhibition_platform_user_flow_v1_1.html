Overview

MVP 사용자와 페이지 범위

가입 시점에는 관람객과 작가를 나누지 않고 통합 회원으로 받습니다. 전시 등록을 원하는 사용자는 서비스 내부에서 작가 권한을 요청합니다.

Primary user

전시를 찾는 관람객

홈, 검색 결과, 지도, 전시 상세, 작품 탐색을 거쳐 예약 또는 문의로 전환됩니다.

  • 예약은 로그인 회원만 가능
  • 반복 노쇼 기록이 있으면 예약 CTA 제한
  • 비회원은 저장, 예약 단계에서 가입/로그인으로 유도
Growth user

전시를 올리고 싶은 회원

통합 회원 가입 후 마이페이지 또는 등록 CTA에서 작가 권한 요청을 진행합니다.

  • 권한 승인 전: 등록 폼 접근 제한
  • 권한 승인 후: 전시 등록 Stepper 진입
  • 전시 유형에 따라 수정/판매 제약 안내
System support

운영/심사 흐름

작가 권한, 갤러리 초대전/기획전 수정 승인, 노쇼 제한 상태를 관리합니다.

  • 작가 권한 요청 검토
  • 갤러리 제공 정보 일치 체크 확인
  • 반복 노쇼 예약 제한 정책 적용
Core flows

핵심 User Flow

MVP의 우선순위는 전시, 작품, 작가 순서입니다. 모든 흐름은 전시 발견과 방문 전환을 중심으로 연결됩니다.

Flow 01 · Discovery to reservation

관람객: 전시 발견 → 상세 → 작품 탐색 → 예약

1

홈 진입

Hero, 오늘의 발견, 근처 전시, 활성 카테고리 칩을 확인합니다.

2

필터 선택

날짜, 장소, 큐레이션 여부를 선택해 검색 결과로 이동합니다.

3

결과/지도 탐색

리스트와 Naver Map 기반 위치 보조 탐색을 함께 제공합니다.

4

전시 상세

전시 소개, 기간, 장소, 작품, 예약 가능 여부를 확인합니다.

5

예약 CTA

로그인 여부와 노쇼 제한 상태에 따라 예약 가능/불가가 결정됩니다.

Flow 02 · Auth and onboarding

공통 회원: 가입/로그인 → 관심사 온보딩

1

가입 진입

예약, 저장, 등록하기 CTA 또는 프로필 메뉴에서 인증 화면으로 이동합니다.

2

인증 방식 선택

네이버 가입 또는 이메일 가입 중 하나를 선택합니다.

3

통합 회원 생성

기본 역할은 member이며, 가입 시 작가/관람객을 분리하지 않습니다.

4

관심사 질문

전시보기, 작품 보기, 전시 올리기 중 접근 목적을 선택합니다.

Flow 03 · Artist permission

회원: 전시 등록 CTA → 작가 권한 요청 → 등록 가능

1

등록하기 클릭

Header, Bottom Tab, My 페이지에서 진입할 수 있습니다.

2

권한 확인

artistStatus가 approved인지 확인합니다.

3A

미승인

작가 권한 요청 폼으로 이동하고 등록 폼은 잠급니다.

3B

심사/승인

운영자가 요청 내용을 검토하고 승인 또는 보완 요청합니다.

4

등록 Stepper

승인된 작가만 전시 정보, 작품 정보, 예약 설정으로 이동합니다.

Flow 04 · Exhibition registration

작가: 전시 등록 → 유형별 확인 → 공개

1

전시 정보

전시명, 기간, 장소, 소개, 대표 이미지를 입력합니다.

2

분류 입력

카테고리: 회화, 사진, 조각, 복합 등. 유형: 대관형, 초대/기획전, 페어형.

3

작품 정보

작품명, 재료, 가격, 판매 여부, 가격 숨김 여부를 등록합니다.

4

예약 설정

관람 가능 시간, 회차 정원, 문의 가능 채널을 설정합니다.

5

검토/공개

초대/기획전이면 갤러리 제공 정보 일치 체크 후 제출합니다.

Flow 05 · Reservation guard

예약: 회원 전용 예약과 반복 노쇼 제한

1

예약하기

전시 상세의 ReservationWidget에서 예약 CTA를 누릅니다.

2

로그인 확인

비회원이면 네이버/이메일 가입 또는 로그인으로 이동합니다.

3

노쇼 확인

반복 노쇼 제한 상태면 예약을 막고 문의/해제 안내를 제공합니다.

4

예약 확정

회차 선택, 인원 입력, 확인 후 My 예약 내역에 저장됩니다.

Rules

주요 분기와 정책 로직

API가 없는 MVP 프로토타입에서도 화면 데이터 배열을 기준으로 활성 카테고리와 예약 제한 상태를 표현할 수 있습니다.

Category visibility without API

활성 카테고리 칩 노출 로직

전시 등록 시 입력된 카테고리 중, 오늘 진행 중인 전시에 포함된 카테고리만 홈에 노출합니다. 해당 카테고리의 당일 활성 전시가 0개이면 칩을 숨깁니다.

today = currentDate() activeExhibitions = exhibitions.filter(exhibition => exhibition.startDate <= today && exhibition.endDate >= today && exhibition.status === "published" ) activeCategories = unique( activeExhibitions.flatMap(exhibition => exhibition.categories) ) render(CategoryChips, activeCategories)
Reservation restriction

회원 전용 예약과 노쇼 제한

예약 CTA는 로그인 회원에게만 활성화됩니다. 반복 노쇼 사용자는 예약 생성 전에 제한 상태를 확인하고 예약 확정을 차단합니다.

if (!user) redirect("/auth") if (user.reservationStatus === "restricted") { showRestrictionMessage() disableReservationSubmit() } if (selectedSlot.capacity > selectedSlot.reservedCount) { createReservation(user.id, exhibition.id, selectedSlot.id) }
전시회 유형 등록 가능 주체 수정 정책 판매 기능 고려사항 필수 확인
개인 대관형 전시 승인된 작가 작가 직접 수정 작가가 가격, 판매 여부, 문의 조건을 직접 관리 기본 전시 정보와 예약 조건 확인
갤러리 초대전/기획전 전시 승인된 작가 또는 갤러리 협업 작가 승인 후 수정 전시 내용, 작품 가격 수정은 승인 플로우 필요 추후 판매 기능에도 갤러리 정책 기반 제약이 생길 수 있음을 데이터 구조에 반영 "갤러리에서 제공하는 정보와 동일하게 입력하였습니까?" 체크박스
페어형 전시 승인된 작가 또는 참여자 행사 조건 우선 부스/기간/공동 운영 정보 확인 부스 단위 판매, 공동 문의, 외부 결제 연결 가능성 고려 행사명, 부스 정보, 참여 작가 정보 확인

Data model hints

다음 와이어프레임/프로토타입을 위한 데이터 항목

실제 API가 없더라도 정적 데이터 또는 클라이언트 상태로 프로토타입 검증이 가능한 최소 필드입니다.

User

회원

  • authProvider: naver | email
  • role: member
  • interests: exhibition_view | artwork_view | exhibition_upload
  • artistStatus: none | pending | approved | rejected
  • reservationStatus: normal | restricted
Exhibition

전시

  • categories: painting, photo, sculpture, mixed...
  • exhibitionType: private_rental | gallery_invited | fair
  • curationAvailable: true | false
  • venue: address, district, naverMapPosition
  • status: draft | submitted | published | ended
Reservation

예약

  • userId, exhibitionId, slotId
  • status: requested | confirmed | cancelled | visited | no_show
  • partySize, reservedAt
  • noShowPolicySnapshot
  • restrictionReason
